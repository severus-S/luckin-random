# 安全与可靠性边界

2026-11-05。当前仍是未进行官方下单/支付验收的开发版本，不是生产安全认证。

## 已实现

- 默认离线 Mock；后端默认 Mock，allowLive、contractVerified、用户 realOrdersEnabled 均关闭；emergencyStop 默认开启。
- 服务端官方预览决定整数分金额，限制单杯/每日/每周/每月和每日数量；默认每日一单。未支付、未知结果保留预算，未知结果禁止再次创建。
- UUID 幂等、单进程互斥、创建前状态落库、任务 slot 唯一键；危险操作无自动重试，已知官方订单 ID 仅查询恢复。
- 服务端每次创建前重查紧急停止、任务授权/修改、门店/候选启用、预算。
- API 强随机 Bearer 配对密钥、恒时比较、每来源每分钟 120 请求、1MiB 请求上限、无 CORS、拒绝 Origin、无 Cookie、无缓存、通用异常不输出上游响应。
- 服务只绑定 loopback，通过本机 HTTPS 反代对外服务。代理必须覆盖而非透传 X-Forwarded-Proto；应用不信任公网客户端自行声明 HTTPS。
- 官方令牌验证成功才 AES-256-GCM 加密落库，32 字节随机主密钥独立环境保存，AAD 绑定 secret 名称；撤销本地副本同时停单。官方撤销需用户在平台完成。
- 客户端配对密钥存在 Keychain，设备专用，JSON 配置及备份不含 Token/密钥；HTTPS 且拒绝重定向，临时 URLSession 无 Cookie 和磁盘缓存。
- iOS JSON 原子写入与文件保护；坏文件不覆盖、未知版本拒绝，恢复配置默认解除真实授权。
- 仅官方域 HTTPS 付款二维码可展示；不使用钱包私有参数、不存支付密码、不把 App Face ID 当作付款授权。

## 部署前必须验收

该服务是单用户实例，API 密钥拥有全部配置及订单权限；不同用户必须独立实例/密钥/数据库/加密主密钥，不能混成多租户或横向扩容。
主机用户权限、磁盘加密、备份加密、防火墙、反代 TLS、进程守护、单进程约束、密钥轮换和数据库持久磁盘需要按最终部署环境验证。
API 密钥轮换：更新服务环境并重启，用户重新配对。令牌失效只报重新授权，不自动登录；服务端主密钥不能随意替换，否则旧 Token 无法解密，应先撤销并重新授权。
订单详情和付款二维码可能含敏感信息，数据库及其 WAL/SHM、服务端备份与手机备份均不应公开分享。当前 Token 加密，订单明文受主机权限保护；若部署有更高要求，需启用主机磁盘加密或加密数据库。
不得使用 `LIVE_CONTRACT_VERIFIED=true` 掩盖未经验证的字段。缺货、门店关闭、优惠失败等目前依赖官方详情/预览成功判断，缺少独立营业/库存字段时不声称已逐项验证。
无官方幂等 key 和无订单 ID 的创建超时无法自动对账；本版本保守锁住新单，人工对账后需专门审计恢复流程，不能直接清空数据库。
当前站内通知箱不等于远程推送。服务端轮询有官方 ID 的活动订单状态，App 前台读取服务端更新；官方实测、无人值守支付提醒和真机取餐展示仍需验收。

## 测试与禁止事项

自动测试全部 Mock，隔离随机 key、临时 SQLite；不得在 CI 注入官方 Token/Apple 凭据。
禁止记录 Authorization、Token、密码、真实设备标识、完整付款链接或个人订单详情到公开日志。
禁止通过改 SKU、绕过 switch、改造二维码、提高预算、模拟钱包操作来规避官方约束。
用户电脑屏幕和手机操作由本人执行；代理不自动点击、输入或操控 GUI。
