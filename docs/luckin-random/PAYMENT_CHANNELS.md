# 支付渠道核查与缺失的接入条件

更新：2026-11-05，Asia/Singapore。**尚未解决同机一键支付；本轮没有新增订单或扣款，也没有完成任何钱包真机支付。**

## 实际核查

1. 对此前已取消订单的官方 QR 图片只做读取、解码和分类。载荷是微信 Native 支付码；只留存类型、主机、路径及查询键名称，不留存或展示私有支付 URI。
2. 向同一官方 QR 图片地址分别发送 iPhone Safari、微信和支付宝 User-Agent。三次均返回相同 PNG、没有重定向。该检查只是 HTTP 表现，不能冒充三个客户端的真机支付测试，也不能用已取消订单验证扣款。
3. 复核瑞幸公开工具 schema 与当前官方文档：创建参数没有支付渠道、支付宝、银联或银行卡参数。公共页面中的一个 payType 示例占位值不构成工具能力，不据此拼接请求。
4. 从瑞幸官方安装入口读取 manifest，按其 SHA256 校验 CLI 0.0.1 Windows 包，仅解压至本机忽略目录并运行帮助命令，没有运行安装、登录、创建、取消或付款。官方 order 子命令只有 preview/create/detail/cancel，create 帮助没有支付渠道选择或另行支付命令。
5. 读取支付宝官方 MCP 包 README 与银联官方接入材料。两者是收款商户/服务商接入能力；当前没有瑞幸对本应用的相应交易及收款授权，不能以自建商户收款单冒充已支付瑞幸订单。

## 分渠道结论

| 渠道 | 目前确认的情况 | 缺少的条件/下一步 |
|---|---|---|
| 微信 Native 扫码 | 前一订单二维码类型已确认；微信规定扫码调起，不支持点击 code_url、长按或相册识别 | 有效新订单下，另一屏幕展示后手机扫码；这是人工备用路径，不满足同机一键目标 |
| 微信 H5 / App 直接付款 | 是不同于 Native 的支付产品，不能把旧二维码改造成该类交易 | 瑞幸提供该笔订单的正式 H5 收银台或本应用可用的 App 支付接入 |
| 银行卡经微信支付 | 微信文档说明进入收银台后可选零钱、银行卡等 | 仍需合法调起有效收银台，由用户选择卡并验密；未进行卡支付实测 |
| 支付宝 | 当前瑞幸接口没有已验证的支付宝收银台、订单串或交易号入口 | 瑞幸提供该笔订单对应的支付宝官方支付信息或授权接入；不得把微信 Native 码转换成支付宝交易 |
| 银联/云闪付/银行 App | 银联支持正规商户 SDK/收银台接入 | 缺瑞幸订单的相应受理及交易信息；尚未进行真机或扣款测试 |
| Apple Pay/其他第三方 | 当前没有收到该订单相应的可用入口 | 需商户支持和对应授权支付交易；不以打开 App 或显示支付界面当作付款成功 |
| 瑞幸官方 App 接管付款 | 用户已确认此前 MCP 取消订单出现在同账号官方订单列表 | 用户已确认可见旧订单；0.1.1 提供官方登记的 App 打开入口，真机打开及新单官方收银台仍待测试 |

## 官方依据

- [微信 Native 常见问题](https://pay.wechatpay.cn/doc/v3/partner/4013352076)：不支持点击 code_url、相册或长按识别支付。
- [微信 Native 产品介绍](https://pay.wechatpay.cn/doc/v3/partner/4012076267)：实际扫码进入收银台后可选择零钱/银行卡并验密。
- [微信 Native 接入易错点](https://pay.wechatpay.cn/doc/v3/partner/4054257719)：同设备场景应采用 H5 或 App 支付。
- [银联线上收银台](https://open.unionpay.com/tjweb/acproduct/list?apiSvcId=3021&index=4)：商户 SDK/收银台方案支持银行 App、云闪付与手机 Pay。
- [支付宝支付 MCP 官方说明](https://opendocs.alipay.com/open/0go80l)，配套官方包 `@alipay/mcp-server-alipay` 的 README 明确收款商户身份和密钥等前提。
- [瑞幸官方工具文档](https://open.lkcoffee.com/docs)、[官方 CLI](https://open.lkcoffee.com/cli)：本轮检查的公开入口；文档资产和 CLI manifest 位于官方页面提供的 CDN/下载 URL。
